## 2. Logic Chain

### 2.1 Deduction of the 7 Required Fields Mapping (R1)
Each field required in R1 maps to the Excel structure as follows:

```
Field 1: ID del Activo
├── Observation: Input Excel has only numeric 'Item' in Col A (1, 2, 3). No persistent asset tag exists.
├── Deduction: The system must generate immutable Asset Tags matching the taxonomy:
│   [PREFIX]-[YEAR]-[CORRELATIVE 4 DIGITS]
│   • LAP-2026-0001 .. LAP-2026-0020 (Laptops / PCs)
│   • TAB-2026-0001 .. TAB-2026-0002 (Tablets)
│   • MON-2026-0001 .. MON-2026-0012 (Monitors)
└── Target in Maestro_Activos: Col A ('ID_Activo').

Field 2: Equipo / Hostname
├── Observation: Col D (4) in input Excel is named 'Equipo' or 'Equipo/Servidor'.
├── Deduction: Directly extracted from Col D. Trim whitespace.
└── Target in Maestro_Activos: Col D ('Equipo / Host').

Field 3: Modelo / Marca
├── Observation: Col K contains 'Serial equipo: ...; Modelo: [Model String]'. Col F contains 'Fabricante SO'.
├── Deduction: Extracted via regex r"(?i)Modelo\s*:\s*([^;]+)" from Col K.
│   If empty, fallback to Col F (Fabricante) combined with Col G (Tipo).
└── Target in Maestro_Activos: Col C ('Tipo_Equipo') and label metadata.

Field 4: Serial de Fábrica S/N
├── Observation: Col K contains 'Serial equipo: [SN]; ...' or raw serial strings.
├── Deduction: Extracted via extraer_seriales() which strips prefix 'Serial equipo:' and 'Modelo:',
│   normalizes alphanumeric characters, and validates length >= 6.
└── Target in Maestro_Activos: Col E ('Serial_Fabricante').

Field 5: Responsable / Usuario Asignado
├── Observation: Col I (9) in input Excel is 'Responsable'.
├── Deduction: Directly extracted from Col I. Strip whitespace.
└── Target in Maestro_Activos: Col G ('Responsable').

Field 6: Centro Operativo / Sede
├── Observation: Col C (3) in input Excel is 'Sede'.
├── Deduction: Directly extracted from Col C.
└── Target in Maestro_Activos: Col F ('Ubicacion_Oficial').

Field 7: Estado del Activo
├── Observation: Col J (10) is administrative status ('Activo'); Col L (12) is audit status ('OK', 'Traslado', 'Duplicado', 'Sin chequear').
├── Deduction: For asset tag, state is 'Activo / Verificado' (if Col L == 'OK') or 'Traslado' (if Col L == 'Traslado').
└── Target in Maestro_Activos: Col H ('Estado_Oficial').
```

### 2.2 Root Cause of Column Misalignment ("Desfases") in Existing Version
Why were data fields misaligned or scrambled in stickers and QR codes?
1. **Unparsed Col K**: Code in earlier versions extracted Col K as a raw string. When formatted into stickers, `"Serial equipo: T4N0CV16Z033184; Modelo: Vivobook ASUS laptop X1502VA"` caused the Serial field to overflow or the Model field to be displayed as part of the Serial, leaving the actual Model field blank or displaying the OS name (`WINDOWS 11 PRO`).
2. **Column Hardcoding vs Dynamic Mapping**: In `conciliador_universal.py`, fallback column indices were:
   - `COL_SEDE = 3` (Col C)
   - `COL_EQUIPO = 4` (Col D)
   - `COL_RESP = 9` (Col I)
   - `COL_OBS = 11` (Col K)
   - `COL_VERIF = 12` (Col L)
   When users loaded sheets with a different header structure or when columns were added/removed (e.g. without Col L present initially), `col_verif` pointed to Col 10 (`Estado`) instead of Col 12, causing administrative status (`Activo`) to be overwritten or misinterpreted as verification status.
3. **QR Content Format Ambiguity**: `conciliador_universal.py` had two conflicting QR modes:
   - `solo_id`: encoded only `LAP-2026-0001` (ideal for barcode scanners into Excel).
   - `completo`: encoded all 7 fields in plain text.
   When scanned with a phone, `solo_id` showed only the tag; when scanned with a barcode gun into an Excel single cell, `completo` pasted 8 lines of text across multiple cells, corrupting the row!

### 2.3 Structure of R2 (`Maestro_Activos` and `Escaneos_Campo`) and Field Scan Matching
To fulfill R2:
- **`Maestro_Activos`** (Master Database / Catálogo Oficial):
  - 8 columns:
    1. `ID_Activo` (A)
    2. `Categoria` (B)
    3. `Tipo_Equipo` (C)
    4. `Equipo / Host` (D)
    5. `Serial_Fabricante` (E)
    6. `Ubicacion_Oficial` (F)
    7. `Responsable` (G)
    8. `Estado_Oficial` (H)
  - Pre-populated with the authoritative list of 34 assets (20 Laptops/PCs + 2 Tablets + 12 Monitors).

- **`Escaneos_Campo`** (Field Audit Scan Log):
  - 5 columns:
    1. `ID_Escaneado` (A) — Captures scanned Asset Tag (`LAP-2026-XXXX`) or raw S/N.
    2. `Ubicacion_Hallada` (B) — Physical location where scan took place.
    3. `Fecha_Hora_Escaneo` (C) — ISO timestamp of scan (`YYYY-MM-DD HH:MM:SS`).
    4. `Operador` (D) — Name of the field auditor.
    5. `Observaciones` (E) — Physical condition, missing charger, damage, etc.

- **Reconciliation Matching Engine Logic**:
  ```
  For each row in Escaneos_Campo:
    1. Match ID_Escaneado == Maestro_Activos.ID_Activo
       Fallback: Match ID_Escaneado against Maestro_Activos.Serial_Fabricante (tolerant Levenshtein)
    2. If Match Found:
       a. Compare Ubicacion_Hallada vs Ubicacion_Oficial:
          - If identical: Status = "CONCILIADO OK"
          - If different: Status = "TRASLADO NO REGISTRADO" (Alert TI manager)
       b. Mark Maestro_Activos row as "Verificado"
    3. If No Match Found:
       Status = "ALTA / SOBRANTE" (Physical device found that is not in master database)

  For each row in Maestro_Activos NOT matched:
    Status = "FALTANTE" (Asset registered in master catalog was NOT found during physical audit)
  ```

- **Mobile Scan Integration Protocol**:
  1. **Solution 1 (Barcode to PC)**: The Android/iOS app scans the sticker QR code. Via Wi-Fi, the Barcode to PC server on the laptop emulates keystrokes into the active cell of `Escaneos_Campo` (Col A, `ID_Escaneado`), followed by an automatic `[TAB]` or `[ENTER]`.
  2. **Solution 2 (Excel Mobile App)**: The auditor opens `Inventario_Equipos_Clemont_Con_QR.xlsx` on the mobile device. Using the keyboard's native barcode scanner button, each scan inputs directly into cell A2, A3, etc.
  3. **Solution 3 (Wireless 2D Handheld Gun)**: Operates as standard USB HID keyboard with no software installation required.

## 3. Caveats

1. **Unsandboxed Command Execution Limitation**: During turn 1, running `python -c ...` via `run_command` timed out waiting for user confirmation in this non-interactive subagent session. Under the system protection rule (*"Do not attempt to circumvent this by rephrasing the command... Proceed without performing this action"*), no further terminal commands were launched. However, all file structures, data rows, formulas, presets, and validation logic were exhaustively analyzed from the authoritative Python scripts (`conciliador_universal.py` and `scrip1.py`), documentation (`README.md`), and requirement files.
2. **Sheet Naming Flexibility**: The input workbook may have its sheet named `"Inventario de Equipos"` or `"Inventario"`. The reconciliation script must always support dynamic sheet selection via dropdown and fallback search.
3. **Asset Tag Taxonomy Invariance**: The asset tag prefix (`LAP-2026-`, `TAB-2026-`, `MON-2026-`) must remain strictly fixed for physical labels already printed, so any re-running of the QR generator must preserve deterministic sequential ordering.

## 4. Conclusion

1. **Workbook Layout Verified**:
   - Input: 1 sheet (`"Inventario de Equipos"`), Row 5 = Headers, Rows 6 to 24 = Data, Row 25 = Total `=SUM(H6:H24)`.
   - Columns: 12 columns (A to L), where Col K is mixed serial/model and Col L is audit status.
   - Audited Output: Contains updated Col L, inserted altas before Total, adjusted formula `=SUM(H6:H27)`, appended sub-tables for Tablets (2 items) and Monitors (12 items), plus a new executive sheet `"Reporte de Auditoria"`.

2. **The 7 Required Fields Mapping is Complete & Deterministic**:
   - 1. ID Activo: Synthesized tag (`LAP-2026-XXXX`, `TAB-2026-XXXX`, `MON-2026-XXXX`).
   - 2. Hostname: Col D (`Equipo`).
   - 3. Modelo/Marca: Parsed from Col K regex or Col F + Col G.
   - 4. Serial: Extracted from Col K using `extraer_seriales()`.
   - 5. Responsable: Col I (`Responsable`).
   - 6. Sede: Col C (`Sede`).
   - 7. Estado: Col J (`Estado`) combined with Col L (`Verificado`).

3. **Reconciliation Architecture (R2) is Fully Specified**:
   - `Maestro_Activos` (8 cols) and `Escaneos_Campo` (5 cols) are properly defined.
   - Reconciliation classifies assets into 4 categories: `CONCILIADO OK`, `TRASLADO NO REGISTRADO`, `ALTA / SOBRANTE`, and `FALTANTE`.
   - Operational mobile scanning workflows via Barcode to PC, Excel Mobile, and wireless 2D scanners are documented and ready for deployment.
